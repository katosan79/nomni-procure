## PurchaseOrder lifecycle

```
draft
  → submitted          (outlet submits)
  → pending_approval   (if value ≥ group threshold)
  → approved           (HQ approves or auto-approved)
  → sent               (transmitted to supplier)
  → partially_delivered (first GRN recorded, order still open)
  → delivered          (all lines GRN'd)
  → closed             (matched against invoice)

From any state → cancelled
```

## Invoice 3-way match

The Invoice Agent (`Mara`) compares:

```
InvoiceLine.unitPrice  vs  PurchaseOrderLine.orderedUnitCost   → price variance
InvoiceLine.qty        vs  GoodsReceiptLine.receivedQty         → quantity variance
InvoiceLine.itemRef    vs  InternalItem.buyerName               → item match (fuzzy)
```

Match tolerance is configurable per outlet group (default: ±2% on price, ±0 on quantity).

## Communication & activity

Every PO has:

- **Comments thread** — user-to-user messages attached to the order
- **Activity timeline** — immutable log: every status change, line edit, approval, note; includes agent actions with `agentId` and `rationale`

The activity timeline cannot be edited or deleted. It is the audit trail.
