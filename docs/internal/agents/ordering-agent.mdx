---
title: Otto — Ordering Agent
description: Drafts purchase orders based on par levels and current stock.
---

## What Otto does

Otto monitors stock levels across outlets and generates draft purchase orders when stock falls below par. It selects the preferred supplier per item, respects delivery schedules, and groups line items by supplier into separate POs.

## Triggers

| Trigger | Condition |
|---|---|
| **Schedule** | Runs nightly per outlet group on configured days |
| **Par alert** | Triggered when a GRN or stock count pushes an item below par |
| **Manual** | HQ Admin or Outlet Manager explicitly requests a draft |

## Algorithm

```
for each outlet in group:
  for each InternalItem with a ParLevel for this outlet:
    currentStock = latestStockSnapshot(internalItemId, outletId)
    parLevel = ParLevel.qty
    if currentStock < parLevel:
      deficit = parLevel - currentStock
      preferredSku = SupplierSkuLink where isPreferred=true for this outletGroup
      draftLine = { internalItemId, supplierSkuLinkId: preferredSku.id, orderedQty: deficit }

  group draftLines by supplierId
  for each supplier:
    create PurchaseOrder { status: 'draft', agentDraft: true, agentRunId }
    attach draftLines
    post AgentAuditEntry
```

## What Otto never does

- Submit an order (status stays `draft` until a human approves)
- Change a preferred supplier without instruction
- Order items with no par level configured
- Generate an order for an outlet it doesn't have permission for (AG-6)

## Auto-approve threshold (AG-7)

If `autoApplyThreshold > 0` and `order.totalValue < autoApplyThreshold`:
- Order is auto-approved to `approved` state
- Undo window: 15 minutes
- Activity timeline records: `auto_approved_by_agent` with rationale

## UI surface

Otto's drafts appear in the **Orders** screen with an "Agent draft" badge. The agent card on the Dashboard shows Otto's pending suggestion count. On the order detail, every line has a `suggestedByAgent: true` flag — the user can see which quantities were suggested vs manual.

## Edge cases

| Scenario | Otto's behaviour |
|---|---|
| No preferred supplier for an item | Skip item, add to `skippedItems` in audit log |
| Item has no SupplierSkuLink at all | Skip item (CK / in-house item) |
| Outlet has a delivery restriction on this day | Defer to next eligible delivery day |
| Group is in HQ Mode but outlet has local exception items | HQ items follow HQ par; local exception items follow outlet par |
