---
title: Vera — Variance Agent
description: Computes actual vs theoretical stock usage and surfaces anomalies.
---

## What Vera does

After each stock count is submitted, Vera computes the variance: actual stock found minus what the system theoretically expects based on opening stock, GRNs, and POS-driven recipe depletion.

## Trigger

```typescript
// Listens to:
{
  type: 'stock_count.submitted',
  countId,
  outletId,
  quality: 'full' | 'partial' | 'estimated',
  submittedAt
}
```

Vera also runs on a weekly schedule for outlets with no recent count (flags as "no count data").

## Variance calculation

```
theoretical_closing = opening_stock
                    + Σ(GoodsReceiptLine.receivedQty for period)
                    - Σ(PosMapping-driven recipe depletion for period)
                    - Σ(recorded adjustments)

variance = actual_closing - theoretical_closing
variance_pct = variance / theoretical_closing
```

Recipe depletion is calculated from POS sales × `RecipeIngredient.qty × yieldFactor`.

## Anomaly detection

Vera flags variance above the configured tolerance (default: ±5% by value). For each flagged item:

1. Check if a GRN is missing (order received but no GRN recorded)
2. Check if a stock adjustment is missing (known waste or spoilage)
3. Check count quality (`partial` or `estimated` counts are lower confidence)
4. Check historical pattern (is this item consistently over/under?)

The anomaly card shows:
- Item name, variance amount, and variance %
- Most likely cause (ranked)
- Suggested resolution

## Count quality weighting

Variance from a `full` count is treated as high-confidence. Variance from a `partial` count is flagged with lower confidence and shown as "indicative only" in reports.

## UI surface

Vera's findings appear in:
- **Inventory → Analytics** — variance heatmap by item and outlet
- **Dashboard** — Vera's agent card with pending anomaly count
- **Reporting** — variance summary section

## Edge cases

| Scenario | Behaviour |
|---|---|
| No POS mapping for a sold item | Theoretical depletion = 0 for that item (gap flagged separately by Sloan) |
| Production batch run recorded | Treats as GRN for output item, depletion for input items |
| Item has no POS link (in-house use only) | Manual adjustment records are the only depletion source |
| Partial count submitted | Calculates variance only for counted items; others marked "not counted this period" |
