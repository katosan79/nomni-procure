## Prototype tech

The prototype is static HTML served from GitHub Pages. No framework, no build step — every screen is a self-contained `.html` file loading shared CSS and JS from `/shared/`.

```
/screens/          45 HTML files — one per screen
/shared/
  tokens.css       Design token CSS variables (v3)
  components.css   Component classes built on tokens (v3)
  shell.js         Persistent nav, role switcher, drawer helpers (v6)
```

The prototype URL: `https://katosan79.github.io/nomni-procure/`

## Design system

**Nomni Design System v1.6.0**

### Colour tokens (Tier 2 — use these in components)

| Token | Light value | Role |
|---|---|---|
| `--surface` | Porcelain #FFFFFF | Cards, panels |
| `--surface-soft` | App cream #F5F2EF | Page background |
| `--text` | Seaweed #0E3727 | Primary text · 12.8:1 |
| `--text-soft` | Forest 70% | Secondary text · 6.3:1 |
| `--text-accent` | Fern #129B41 | Accent text, active states |
| `--border` | Forest 14% | Hairlines |

Status tokens: `--status-ok-fg` (Spinach) · `--status-warn-fg` (Sun) · `--status-risk-fg` (Rose)

**Never use raw hex values in components.** Every colour must come from a CSS variable.

### Spacing tokens (8px base, t-shirt names)

`--space-xs` 4px · `--space-sm` 8px · `--space-md` 12px · `--space-lg` 16px · `--space-xl` 24px · `--space-2xl` 32px · `--space-3xl` 48px

### Typography

- **Hanken Grotesk** — UI, headings, body (all weights 300–700)
- **IBM Plex Mono** — PLU codes, SKUs, numeric IDs, code
- Tabular figures required on all KPI values, prices, and table columns

### Content width

| Token | Value | Use |
|---|---|---|
| `--measure-narrow` | 720px | Forms, dialogs |
| `--measure-content` | 1080px | Default HQ module screens |
| `--measure-wide` | 1280px | Dense data dashboards |

## Key UI patterns

### Slide-out drawer

Used throughout for row detail — orders, items, POS outlet, recipe. Pattern:

```css
.drawer {
  position: fixed; top: 0; right: 0; bottom: 0; width: 460px;
  transform: translateX(100%);
  transition: transform 240ms cubic-bezier(0.32,0,0.15,1);
  z-index: 401;
}
.drawer.open { transform: translateX(0); }
```

- ESC key closes the drawer
- Backdrop `z-index: 400` behind drawer at `z-index: 401`
- `document.body.style.overflow = 'hidden'` while open
- Clicking a different row while drawer is open updates content in place (no close/re-open)

### Status pills

All statuses use a pill component: coloured background + text. **Never colour alone** — accessibility requirement.

### Agent surface

Agent-touched content wears: `border: 1px solid var(--agent-border)` + `box-shadow: 0 0 0 3px var(--agent-glow)`. Named agent identity (avatar + name) always present. Two states:
- **Ready to approve** — glow active, Spring-coloured `.btn-ai` CTA
- **Done · reversible** — glow settles, Undo affordance only

## Delivery phases (Strangler Fig)

The product is planned for 6-phase delivery:

| Phase | Scope |
|---|---|
| 1 | Ordering + GRN + basic invoice |
| 2 | Recipe costing + food cost % |
| 3 | Market lists + supplier catalogue |
| 4 | POS mapping + COGS tracking |
| 5 | Agent layer (all 5 agents) |
| 6 | Reporting + accounting export |

Each phase replaces a slice of the existing system (Strangler Fig pattern). Phase 1 must be live before Phase 2 begins.
