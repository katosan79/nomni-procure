## Overview

POS mapping is split into two screens. Sub-nav links between them.

| Screen | File | Purpose |
|---|---|---|
| Configuration | `pos-mapping.html` | Map PLU codes to recipes/items. Edit + save. |
| Monitoring | `pos-mapping-monitoring.html` | Health check, sync status, COGS impact. Read-only. |

---

## Configuration screen

**Canvas:** `data-measure="wide"` (1280px)

### Layout

Two-column grid: 320px sticky left panel + scrollable right column.

### Left panel

**2×2 KPI strip:**
- Total POS Items: 547
- Mapped: 468 (85%)
- Unmapped: 52
- Stale/Partial: 27

**Category coverage chart:** One row per menu category — name, horizontal bar, % coverage. Colour: ≥90% green, 75–89% amber, <75% red. Clicking a row filters the right-column table to that category.

### Right column

**Filter tabs:** All 547 · Unmapped 52 · Partial 16 · Mapped 468 · Ignored 11

**Table columns:** Item name · PLU (IBM Plex Mono) · Menu category · Status pill · Action

**Every row is clickable** → opens the mapping detail drawer.

### Mapping detail drawer

**Width:** 460px, slide-in from right.

Fields:
- Item name, PLU code, menu category, last seen in sales (read-only — from POS sync)
- "Maps to" type toggle: Recipe / Internal Item
- Target: controlled dropdown (no free-text). Options populated from `Recipe` or `InternalItem` tables.
- Modifier groups: for PLUs with variants, each modifier row has its own type toggle + target dropdown
- Outlet overrides section: outlet-level exceptions, same dropdown treatment

**Business rule:** All mapping targets must be selected from controlled lists. Free-text is never accepted — this prevents orphaned mappings.

**Save:** `PUT /pos-items/:id/mapping`

### Sloan agent card

Appears above the table when unmapped items exist. Shows batch suggestion with confidence score per item. Actions: Approve all suggested · Review individually · Dismiss.

## Monitoring screen

**Canvas:** `data-measure="content"` (1080px)

**Read-only.** No push buttons. No config actions. POS config lives in `outlet-detail.html`.

### Section 1 — Health bar

Single-line status: dot colour + "N outlets need attention · X of Y fully synced" + severity chips (e.g. "2 dark", "2 gaps").

Endpoint: `GET /pos-monitoring/summary`

```json
{
  "totalOutlets": 12,
  "fullSync": 8,
  "attentionCount": 4,
  "chips": [
    { "label": "2 dark", "severity": "risk" },
    { "label": "2 mapping gaps", "severity": "warn" }
  ]
}
```

### Section 2 — Attention cards

Cards sorted by severity (dark → sync failure → mapping gap). Each card shows:

- 4px severity bar: `#DC2626` for dark, `#D97706` for gap
- Outlet name + issue description
- **COGS impact line** — e.g. "COGS not tracked for this outlet — 0% of sales mapped to recipes"
- CTA: link to fix location (`outlet-detail.html` for dark, `pos-mapping.html?outlet=X` for gaps)

Endpoint: `GET /pos-monitoring/attention`

### Section 3 — All outlets table

Columns: Outlet · Group · POS System · Last Sync · Coverage (progress bar + X/48) · Status pill

**Every row is clickable** → opens the outlet detail drawer.

Endpoint: `GET /pos-monitoring/outlets`

### Outlet detail drawer

**Width:** 460px.

**Connected outlet state:**

```
POS Connection KV:
  System, Connection type, Connection ID, Status, Last sync, Transactions today

14-day transaction bar chart (inline SVG):
  14 bars, weekend opacity 0.5, weekday opacity 0.28, today opacity 1.0
  Trend polyline connecting bar midpoints
  Dashed avg reference line
  Today dot

Mapping Coverage:
  Progress bar + % + status banner

Recent Sync History:
  Last 4 entries — dot + monospace timestamp + note

Footer:
  "Outlet Settings →" → outlet-detail.html
  "View mapping →" → pos-mapping.html
```

**Dark outlet state:**

```
Red banner: "No POS configured — COGS not tracked for this outlet"
0% coverage section
Footer: "Configure in Outlet Settings →" → outlet-detail.html
```

Endpoint: `GET /pos-monitoring/outlets/:outletId/detail`

```json
{
  "outletId": "...",
  "name": "Bondi Beach",
  "status": "ok",
  "pos": { "system": "Abacus POS", "connType": "Live API", "connId": "ABX-0042" },
  "lastSync": "2026-06-25T23:58:00Z",
  "txToday": 847,
  "txHistory": [851, 923, 1187, ...],  // 14 values, newest last
  "mappingCoverage": { "mapped": 48, "total": 48 },
  "syncLog": [
    { "at": "2026-06-25T23:58:00Z", "status": "ok", "note": "48 items synced" }
  ]
}
```

### Business rules

1. POS connection config is in `outlet-detail.html` — monitoring drawer is read-only for connection settings
2. `txHistory` is always 14 values (daily totals, newest last). Null for dark outlets.
3. COGS impact line is required on every attention card — never omit it even if the impact is unknown
