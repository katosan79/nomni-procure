## outlets.html

**Access:** HQ Admin only

**Canvas:** `data-measure="content"` (1080px)

### Summary strip

- Total outlets: 12 (demo) / 124 (production)
- Active: 10
- Pending setup: 2
- Outlet groups: 4

### Table columns

Outlet name · Group · Brand · POS system · Last order · Status pill · Health score

Health score = composite of: last count date, GRN completeness, POS coverage, invoice match rate.

**Every row is clickable** → navigates to `outlet-detail.html?id=...`

### Group filter

Tabs or dropdown: All · CBD Cluster · Beachside · Suburban · Ungrouped

## outlet-detail.html

**Tabs:** Overview · Integrations · Inventory · Users · Settings

### Overview tab

KPIs: Last order · Last count · Open invoices · Food cost % (month). Activity timeline.

### Integrations tab

**POS section:**

This is where POS connection configuration lives. The monitoring drawer in `pos-mapping-monitoring.html` links here for "dark" outlets.

Fields:
- POS system (dropdown: Abacus POS / Square / Lightspeed / Toast / Other)
- Connection type (Live API / Nightly export / Manual)
- Connection ID / API key reference (stored as a reference, never the key value)
- Test connection button

**Accounting section:**

Xero: connected / not connected. Connect via OAuth flow (never credentials stored in Nomni).

### Inventory tab

Read-only view of this outlet's current stock, par levels, and recent counts.

### Users tab

Users assigned to this outlet. HQ Admin can add/remove users and change role assignments per outlet.

### Settings tab

Operating mode override for this outlet (if group is Hybrid). Approval threshold. Notification preferences.

## outlet-group-detail.html

**Access:** HQ Admin only

Overview of an outlet group:
- Outlets in group (table with health status per outlet)
- Market list assigned (active + pending)
- Operating mode
- Agent configuration per agent (on/off + thresholds)
- Group-level reporting summary

---

## Key business rule

**POS configuration lives in `outlet-detail.html → Integrations`.**

The POS Mapping screens read POS connection state but never write it. Connection credentials are never stored in Nomni — only a connection reference ID. Actual auth is handled via the POS system's OAuth or API key stored in a secrets manager; Nomni stores only a pointer.
