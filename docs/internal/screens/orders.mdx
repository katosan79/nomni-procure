## Orders list (`orders.html`)

**Canvas:** `data-measure="content"` (1080px)

### KPI strip

- Orders this month: 847
- Pending approval: 12
- Awaiting delivery: 34
- Total value this month: $284,192

### Filter bar

Tabs: All · Pending Approval · In Progress · Delivered · Cancelled

Secondary filters: Date range · Outlet · Supplier · Agent draft (toggle)

### Table columns

| Column | Notes |
|---|---|
| Order # | e.g. PO-2026-00847 · IBM Plex Mono |
| Outlet | Outlet name |
| Supplier | Supplier name |
| Items | Line count |
| Value | AUD, right-aligned, tabular figures |
| Delivery date | |
| Status | Status pill |
| Agent badge | "Agent draft" chip if `agentDraft: true` |

**Every row is clickable** → navigates to `order-detail.html?id=...`

### Endpoint

`GET /purchase-orders?outletId&status&supplierId&agentDraft&dateFrom&dateTo`

## Order detail (`order-detail.html`)

### Header

Order number · Outlet · Supplier · Status pill · Created by · Created at

### Line items table

Columns: Item name · Supplier SKU (IBM Plex Mono) · Ordered qty · Unit · Unit cost · Line total · Received qty · Discrepancy flag

Discrepancy flag = orange chip "Short N units" or "Over N units" when GRN qty differs from ordered qty.

### GRN section

Rendered after first partial GRN. Shows:
- Received date, received by
- GRN lines with actual quantities
- Any discrepancy notes

### Approval section (pending_approval state only)

Shows approval threshold, order value, and Approve / Reject buttons for HQ Approver role.

### Activity timeline

Immutable log: status changes, agent actions, comments, GRN events.

### Endpoints

- `GET /purchase-orders/:id` — full order with lines
- `GET /purchase-orders/:id/grn` — GRN with lines
- `PATCH /purchase-orders/:id/approve`
- `PATCH /purchase-orders/:id/grn` — upsert GRN lines
- `POST /purchase-orders/:id/comments`

## New order wizard (`new-order.html`)

4-step stepper. Each step is a separate view. Data is held in session state until submission.

### Step 1 — Select outlet and supplier

- Outlet: dropdown filtered to outlets the user has ordering permission for
- Supplier: dropdown filtered to suppliers linked to the selected outlet

### Step 2 — Add items

Par-suggested items appear pre-populated with deficit quantities. User can:
- Accept suggested qty
- Adjust qty (inline number input)
- Remove item (× button)
- Add more items (search dropdown from `InternalItem` catalogue)

Each line shows: Item name · Supplier SKU · Current stock · Par level · Suggested qty → Ordered qty

### Step 3 — Delivery details

- Delivery date (date picker)
- Notes (textarea, supplier-visible)

### Step 4 — Review and submit

Summary card: outlet, supplier, item count, total value, delivery date. Two buttons: Back (edits) · Submit order.

On submit: `POST /purchase-orders` with `status: 'draft'` → immediate `PATCH /purchase-orders/:id/submit`.

### Agent draft integration

If Otto has a draft for the selected outlet + supplier, Step 2 is pre-filled with Otto's suggested lines. User can edit any line. Pre-filled lines have `suggestedByAgent: true` flag shown as a small "AI" chip.
