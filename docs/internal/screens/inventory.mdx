## Three tabs, three screens

The Inventory section has persistent sub-nav across three tabs:

| Tab | Screen | Purpose |
|---|---|---|
| Operations | `inventory.html` | Current stock, adjustments, production runs |
| Analytics | `inventory-analytics.html` | Variance heatmap, Vera agent insights |
| Governance | `inventory-governance.html` | Count templates, par overrides, compliance |

---

## Operations (`inventory.html`)

**Canvas:** `data-measure="content"` (1080px)

### Stock overview

Table: Item name · Category · On-hand qty · UOM · Par level · Days until par · Last updated · Status

"Days until par" calculated from: `(currentStock - parLevel) / avgDailyUsage`. Red if <3 days.

### Adjustments

Floating button: "New adjustment". Drawer with fields: Item · Qty (±) · Reason (dropdown: Waste / Damaged / Correction / Write-off / Production / Transfer) · Notes.

`POST /inventory/adjustments`

### Production batch runs

"Record production" drawer. Fields: Recipe (production batch type only) · Batch qty · Date · Notes.

On submission: decrements input ingredient stock, increments output item stock.

`POST /inventory/production-runs`

## Analytics (`inventory-analytics.html`)

### Variance heatmap

Grid: rows = items, columns = weeks. Cell colour intensity = variance magnitude. Click cell → drill-down to that item × week.

### Vera agent surface

Vera's anomaly cards appear above the heatmap. Each card: item name · variance amount · most likely cause · suggested action.

### Theoretical vs actual chart

Bar chart per item (or category): blue = theoretical usage, green = actual. Gap = variance.

### Endpoint

`GET /inventory/variance?outletId&dateFrom&dateTo&category` — variance by item for the period.

## Governance (`inventory-governance.html`)

### Count templates

List of templates: name · item count · last used · assigned outlets.

"New template" → builder: drag items into template, set count order by storage location.

`POST /inventory/count-templates`  
`PUT /inventory/count-templates/:id`

### Par level overrides

Outlet-level overrides (Hybrid mode only). Table: Item · HQ par · Outlet override · Override by · Override date.

`PUT /inventory/par-overrides/:outletId/:itemId`

### Compliance dashboard

Per-outlet status: last count date · count frequency · outstanding variances · data quality score.

Used by HQ Admin to identify outlets with stale counts or poor GRN discipline.

## Stock count wizard (`new-count-session.html`, `count-sheet.html`)

### new-count-session.html

Fields: Outlet · Count type (Full / Category / Spot) · Template · Date

`POST /stock-counts`

### count-sheet.html

One row per item with: name · last count qty · expected qty (theoretical) · actual qty input · notes.

Submit → `POST /stock-counts/:id/submit` → triggers Vera variance calculation.

### count-session-detail.html

Review submitted count: item × actual × theoretical × variance × variance %. Approve or send back for recount.
