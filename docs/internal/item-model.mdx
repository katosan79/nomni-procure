## The buyer-primary principle

The `InternalItem` is the canonical entity. Every other module joins to it:

```
Orders           → PurchaseOrderLine.internalItemId
Recipes          → RecipeIngredient.internalItemId
Inventory counts → StockCountLine.internalItemId
POS mapping      → PosMapping.targetId (when targetType = 'internal_item')
Market lists     → MarketListLine.internalItemId
Variance         → computes against internalItemId
```

**Never store `supplierSku` as a join key in any of these tables.** If a supplier changes their SKU, only `SupplierSkuLink` needs updating — nothing else breaks.

## SupplierSkuLink

One `InternalItem` can have many `SupplierSkuLink` rows — one per supplier who carries it.

```
InternalItem: "Chicken Breast 500g"
  SupplierSkuLink #1: PFD Foods · SKU: CHK-001 · carton (5kg) · conv: 5 · $18.50/kg · preferred: true
  SupplierSkuLink #2: Thomas Foods · SKU: CB500G-T · 500g each · conv: 0.5 · $19.80/kg · preferred: false
```

**Preferred supplier** is per outlet group, not per item globally. An outlet group in Queensland may prefer Thomas Foods while NSW prefers PFD Foods. The `SupplierSkuLink` table scopes `isPreferred` to `outletGroupId`.

## MarketList

A market list is an HQ-managed pricing document pushed to outlet groups. It does not replace the `InternalItem` — it sets the **approved prices** outlets use when ordering.

```
MarketList: "NSW Metro — Jun 2026"
  status: active
  assignedGroups: [NSW Metro]

MarketListLine: InternalItem("Chicken Breast 500g") · SupplierSkuLink(PFD #1) · approvedUnitCost: $18.50
MarketListLine: InternalItem("Tomatoes 1kg") · SupplierSkuLink(Perfection Fresh) · approvedUnitCost: $3.20
```

When Otto drafts an order, it uses `MarketListLine.approvedUnitCost` as the line cost — not the raw `SupplierSkuLink.lastCost`.

**Push rules:**
- A push does not affect in-flight orders (POs in `submitted`, `approved`, or `sent` state)
- Conflict resolution: "Keep local overrides" or "Overwrite with HQ values" — set at push time
- Activity timeline records every push with HQ actor, timestamp, and diff

## PosItem and PosMapping

`PosItem` rows are synced from the outlet's POS system. They are read-only in Nomni — the POS system is the source of truth for what's on the menu.

`PosMapping` links a `PosItem` to a `Recipe` or `InternalItem` in Nomni. One PosItem can have one mapping.

```
PosItem: PLU "BRG-001" · name "Avocado Toast" · outlet: Bondi Beach
  PosMapping: targetType=recipe · targetId=recipe("Avocado Toast v3") · mappedBy=hq_manual
```

When a POS sale is recorded, Nomni uses `PosMapping` to find the recipe and deplete ingredients from inventory.

**Governance Agent (Sloan)** suggests mappings for new unmatched POS items. These have `mappedBy = agent_suggested` and `confidenceScore` set. They require HQ approval before taking effect.

## Weighted average cost

`InternalItem` doesn't store a single `unitCost` field. Cost is computed by the Invoice Agent as a **weighted average** of recent invoice receipts:

```
weightedAvgCost = Σ(invoiceLine.qty × invoiceLine.unitPrice) / Σ(invoiceLine.qty)
```

This is recalculated after each invoice post and stored in a `ItemCostSnapshot` table (one row per `internalItemId` per `outletGroup` per `period`). Recipes use the snapshot cost for food cost % calculations.

The `Cyrus` agent (Margin Agent) monitors the delta: if a new invoice snapshot shifts an item's cost by more than the configured threshold, Cyrus fires a `price_changed` event to the recipe margin alert pipeline.
